# Scan

## Step 0 — 确认调查范围

从当前请求和项目说明确定仓库、业务入口及已有授权。读取适用工作约定、README、包清单和部署入口。范围缺失时先定位可确认的项目，仅对会改变接入目标的歧义提问。

## 追踪实际请求

1. 用 `rg --files` 查看源码、配置、模板、入口和测试分布。记录当前工作区已有改动、实际部署位置及运行源码版本，选择适合本次写入的工作区。存在相互影响的改动时使用对应版本的隔离工作区。
2. 从项目使用的模型客户端或请求地址查调用入口，沿调用方追到参数构造、模板加载和动态拼接。按项目栈调整检索词，以下词可作为起点。

   ```sh
   rg -n -i 'chat\.completions|responses\.create|messages\.create|chat/completions|llm\.stream|generateContent' <源码目录>
   rg -n -i 'system.?prompt|instructions|messages|role|prompt|模板|提示词' <相关模块>
   ```

3. 从已发现入口补查主助手、子代理、联网合成、工具说明、压缩摘要、分段与汇总、纠错和重试指令。追踪导入的配置文件、数据库字段及 SDK 扩展；动态加载路径按实际代码继续查。
4. 核对活跃入口、历史脚本和测试样例。用实际运行解释器查询模块路径（如 `__file__`）或构建入口，核对安装方式与执行文件版本。无法静态确认的路径记录原因和需要的运行证据，目录名与服务器角色按部署配置确认。
5. 说明每份模板怎样进入请求，哪些部分来自用户输入、原始资料、召回结果、尺寸或时间。遇到仅有结构化模型参数的调用，记录调查结论。

## 交付候选与方案

按用途归并重复调用，每项给出以下信息。

| 信息 | 应提供的证据 |
| --- | --- |
| 用途与候选 ID | 名称、实际任务、建议稳定 ID |
| 来源与调用方 | 文件及行号、模型请求入口、导入或加载关系、运行版本与本地差异 |
| 活跃情况 | 已确认使用、依赖提供、历史入口或尚待确认 |
| 组成 | 模板片段、动态变量、组合顺序、空值与缺省含义、输出格式要求及解析依赖 |
| 存储与读取 | 默认内容、现有覆盖配置、API 与任务的实际存储和挂载、进程或会话缓存、任务开始位置 |
| 更新影响 | 生效单位、中间结果与最终结果缓存、重启和并发条件 |
| 接入改动 | 复用接口和存储、预计修改文件、网络路径、必要验证 |

在清单末尾说明已调查的范围、仍未确认的入口和依据，保留真实覆盖范围。用简短业务例子说明修改后哪项任务会使用新版。

给出所选候选的最小接入建议，优先复用原业务配置、接口与存储。硬编码模板可采用代码默认值加持久化覆盖的方案。用户选择接入范围并确认方案后执行 Integrate，已有明确确认时继续对应工作。
