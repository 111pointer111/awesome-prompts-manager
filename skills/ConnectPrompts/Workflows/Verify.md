# Verify

## Step 0 — 核对运行目标

确认当前源码、实际部署版本、候选范围及验证授权，先运行相关现有检查。优先通过合成材料和可替换模型客户端验证模板读取；真实模型调用、生产修改与部署按已有授权执行。

## 接口与保存

- 缺失或错误 Token 的目录查询、单条查询和修改均返回 401，有效 Token 能读取已接入条目。
- 目录符合 v1，稳定 ID 唯一，返回的是模板及变量说明。逐项核对单条读取结果。
- 合法修改返回实际保存的内容与新版 revision，再次读取一致。
- 两个请求携带同一旧版本提交不同内容时，只允许一个成功，另一个返回 409。无效模板保存失败后，原内容保持可读。
- 恢复默认使用 `content: null`，返回当前默认内容和新版本。重启应用或重建容器后，自定义配置仍然可读。
- 模拟保存响应丢失，通过读取确认最终状态，确保写入流程不会自动重试覆盖其他修改。

## 任务实际使用

沿正常任务入口记录本次实际使用的模板版本或指纹，验证以下过程。

1. 任务 A 开始，取得当前整组模板。
2. 修改并保存其中一项模板。
3. A 的后续模型请求、分段、汇总和纠错继续使用已取得的快照。
4. 新任务 B 读取新版，模型请求构造中实际使用新版内容。
5. 模板改变后，相关中间缓存以新版身份处理，已完成历史结果按原业务规则保留。

记录模板进入模型请求的位置与断言结果。管理接口保存成功、模型请求使用新版和模型输出符合业务预期分别报告。

## 平台联动与交付

从管理平台后端验证实际连接和鉴权，完成添加渠道、目录同步、编辑保存及回读。确认恢复默认、备注独立保存和稳定 ID 关联符合协议。渠道断线时保留最近副本，连接恢复后重新读取原业务。

提供实际执行的检查、结果与证据位置。验证失败时定位到读取、缓存、持久化、协议或网络中的具体原因，修复后复现原触发条件。尚缺真实任务或部署条件时说明影响的结论，交付已完成部分的真实状态。
