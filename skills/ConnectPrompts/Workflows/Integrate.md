# Integrate

## Step 0 — 对齐已确认方案

对照 Scan 的候选和当前授权核对本次范围，保留其他工作区改动。读取仓库协议或随包的 [Protocol.md](../Protocol.md)。使用项目现有路由、存储、模型请求和错误处理结构，按实际差异调整参考实现。

## 接入原业务

1. 为选定模板分配稳定 ID，描述用途、变量、组合顺序、可编辑限制及新任务生效规则。沿用业务原有占位符语法，逐项检查程序定位、替换、输出校验与模板文本的关系。
2. 复用已有覆盖配置和持久化存储。硬编码模板保留为代码默认值，自定义内容保存到数据库事务或原子替换文件中。确定容器重建后仍可访问该存储，接口返回实际保存状态。
3. 把整组模板的读取放在用户确认的任务开始位置，固定到任务结束。检查会话复用、长文分段、综合分析和纠错调用，确保它们取得同一任务快照。
4. 将实际使用的整组模板或版本指纹加入相关缓存身份。沿用历史结果保存规则，用户要求重算时按明确范围处理。
5. 在原业务补齐目录、单条读取和修改接口。每次查改都验证业务专用 Bearer Token，密钥通过现有私有配置注入。版本比较和写入在同一事务或串行临界区完成，409 返回冲突，`content: null` 恢复当前默认值。
6. 接口校验模板长度、变量及程序输出约束。返回可读错误并保留上次有效状态，凭据仅保存在服务端。对写入结果未知的情况，通过读取恢复确认。

## 确认访问路径

| 当前部署 | 接入方案中明确的内容 |
| --- | --- |
| 已有私网 HTTP 服务 | 复用监听和路由，填写平台后端可访问的基础 URL |
| 只监听宿主机回环地址 | 复用本机私网代理，转发提示词管理路径 |
| 只在容器网络内监听 | 明确代理所在网络与目标服务名，或映射到宿主机回环地址 |
| 常驻任务、定时任务缺少 HTTP 服务 | 评估复用同机现有 API，或增加共享同一持久化存储的小型管理接口 |

从平台后端所在环境检查 DNS、网络、证书及 Token。网络条件需要调整时，将必要配置纳入接入方案。已有网关可按原部署约定复用，新增组件应有当前连接需求支持。

## 完成接入

执行 Verify，按结果修正。更新受影响的使用说明、接口约定和部署配置。交付改动范围、验证证据、提交状态、实际部署状态及待确认项。平台添加渠道时使用业务基础 URL 与 Token，新暴露条目通过完整目录同步。
