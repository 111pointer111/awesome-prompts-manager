# ConnectPrompts

从真实模型请求追踪提示词来源，将用户选定的模板接到统一管理协议，保留原业务的存储和任务流程。

## Workflow Routing

| 用户意图 | 工作流 |
| --- | --- |
| 查找、盘点、分析提示词，或首次提出接入 | [Scan](Workflows/Scan.md) |
| 已确认候选与修改方案，开始接入 | [Integrate](Workflows/Integrate.md) |
| 检查已接入项目、排查保存或热更新问题 | [Verify](Workflows/Verify.md) |

## Gotchas

- 沿模型客户端、SDK 扩展和实际调用方追踪。内联用户指令、工具说明、摘要和纠错指令也可能是模板。
- 提示词、运行时资料和程序生成的输出协议分别标明。语音识别或图像识别请求也可能仅有结构化参数。
- 对依赖内提示词使用其配置或扩展点。缺少扩展点时，从可维护源码或项目管理的补丁机制定制，先说明升级影响并确认方案。`node_modules` 和生成目录由安装或构建重建。
- 实际执行代码以运行解释器返回的模块路径或构建入口为依据，核对安装方式和运行版本。
- 模板读取位置决定热更新。进程启动时读取、模块常量和会话缓存需要追到任务开始的实际读取点。
- API 写入与任务读取要落在同一持久存储，核对实际目录、容器挂载及跨进程读取结果。
- 一项逻辑任务及其校验重试固定整组模板。有界续跑、跨周期重试或重启恢复仍属同一任务时，快照随任务持久化到完成。已有提案按原流程继续投递。
- 代码默认值更新也会改变模板。让 `revision` 覆盖当前内容和默认值的变化，可结合存储序号与内容指纹，或在升级时推进版本。
- 占位符语法沿用原业务。部分文本还被程序用于定位、替换或校验，接入方案应列出这些依赖。
- 目录中的稳定 ID 用于平台关联备注，改名和部署保持 ID。备注由平台独立保存。
- 保存超时后通过读取确认实际结果，写入重试可能覆盖更新。版本冲突保留用户编辑内容。
- 浏览器入口可能要求会话或代理身份，平台后端携带管理 Token 时需要验证实际机器访问路径。

## 协议与参考实现

仓库内使用 [协议规范](../../docs/protocol.md)、[Python 示例](../../examples/python/server.py)和 [TypeScript 示例](../../examples/typescript/server.ts)。单独分发本目录时，随包的 [Protocol.md](Protocol.md) 提供 v1 接口约定。在目标项目沿用已有鉴权、路由、配置和错误处理方式。

公开示例使用合成内容，公开配置保留字段模板、变量说明和凭据引用。真实业务内容、运行数据和凭据保存在项目私有运行存储中，提交前检查公开文件和示例边界。

首次运行先定位目标项目和适用工作约定，读取对应工作流。事实可以从源码或运行配置查明时直接调查，影响数据范围、用户功能或部署结果的选择交给用户。已有明确授权覆盖本次方案时据此实施。

## Examples

**仅盘点。** 用户说“找出这个项目所有可能的提示词”。执行 Scan，交付带调用证据的候选清单、范围说明和接入建议，等待用户选择。

**选定后接入。** 用户已确认文章评分与摘要两个候选及方案。执行 Integrate，复用现有数据库和 HTTP 服务补齐协议，再执行 Verify。

**排查热更新。** 用户说“保存成功，新任务仍用旧规则”。执行 Verify，检查任务读取位置、实际使用版本和中间结果缓存，修复后在原触发条件下复查。
