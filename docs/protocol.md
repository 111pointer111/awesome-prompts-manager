# 提示词管理协议 v1

平台配置渠道的基础 URL 和 Bearer Token。以下路径追加到基础 URL 后面，基础 URL 可以包含原业务的路径前缀。所有请求均由平台后端发送，原业务逐次验证 Token，返回 JSON，禁止重定向。

## 获取目录

`GET /v1/prompts` 返回当前允许管理的全部提示词及原始模板。目录包含完整模板，供跨渠道搜索与离线查看。原始文章、聊天内容、密钥和变量实际值由业务自己管理。

```json
{
  "protocolVersion": 1,
  "service": { "id": "example-service", "name": "示例服务" },
  "prompts": [{
    "id": "article-review",
    "name": "文章评分",
    "description": "按当前兴趣评价文章价值",
    "content": "请根据 {topics} 评价文章。",
    "defaultContent": "请根据 {topics} 评价文章。",
    "revision": "0",
    "customized": false,
    "readOnly": false,
    "maxLength": 16000,
    "variables": [{ "name": "topics", "description": "任务开始时取得的兴趣话题" }],
    "composition": ["评分模板", "本次内容偏好", "文章原文作为独立用户消息"],
    "effect": "下一项文章评审开始时使用，同一评审的分段与汇总固定版本"
  }]
}
```

`service.id` 标识业务实例，`prompt.id` 标识可编辑片段。它们在改名、部署、重启时保持稳定。平台将渠道 ID 和提示词 ID 作为备注关联依据。更换地址后如果业务实例标识改变，平台报告不匹配，避免覆盖旧目录和备注。

每次成功同步是完整目录。失联保留最后成功副本，已从目录移除的条目保留备注并标记失效。一个目录最多 1000 项、响应体最多 8 MiB，单个模板最多 131072 个 JavaScript UTF-16 代码单元，具体限制由 `maxLength` 声明。需要更大目录时应先增加分页协议与资源测试。

## 读取与修改

`GET /v1/prompts/{id}` 返回同结构的单条提示词。

`PUT /v1/prompts/{id}` 接收以下对象，成功后返回实际保存的单条提示词。

```json
{ "content": "新的模板，保留 {topics} 变量", "expectedRevision": "0" }
```

`content: null` 恢复当前部署提供的默认值。原业务对版本做原子比较并保存，旧版本返回 HTTP 409。不能用重试写入覆盖冲突。未知 ID 返回 404，无效 Token 返回 401，无效模板返回 400，只读条目的修改返回 403。错误结构为 `{"error":"稳定错误代码","message":"可读说明"}`，错误信息不包含凭据。

保存成功后，平台重新读取原业务确认内容和版本。连接中断时显示结果待确认，通过读取恢复，写操作不自动重试。默认值、变量占位符、程序输出协议的约束由原业务验证。平台保存备注使用独立接口与版本，修改备注不会修改业务提示词。

## 任务与持久化

任务开始时从原业务持久化存储读取所需的整组模板，固定到这项工作结束。后续新任务读取新版。持久化自定义配置与代码默认值分开，重启、重建容器时保留自定义配置。写入采用数据库事务或原子替换文件。

缓存身份包含实际使用的整组模板或其版本指纹。历史已完成结果继续保留，新任务和中间缓存按新版规则处理。管理平台离线不会改变原业务读取本地提示词的流程。
